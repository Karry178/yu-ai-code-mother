🎉 **YuCodeMother v0.8 版本发布说明**

### 📋 版本概述

本次 v0.8 版本是项目的重要功能增强版本，在 v0.7 SSE流式输出的基础上，实现了完整的**应用部署功能**。通过文件复制机制和Nginx静态资源映射，用户可以一键将AI生成的代码部署到服务器，并通过唯一的URL访问已部署的应用，真正实现从"代码生成"到"应用上线"的完整闭环。

### ✨ 新增功能

#### 🚀 应用部署核心功能

**1. Controller 层 - 部署接口实现**

实现了标准的应用部署接口，支持一键部署AI生成的代码：

```java
@PostMapping("/deploy")
public BaseResponse<String> deployApp(@RequestBody AppDeployRequest appDeployRequest, HttpServletRequest request) {
    // 检查部署请求是否为空
    ThrowUtils.throwIf(appDeployRequest == null, ErrorCode.PARAMS_ERROR);
    // 获取应用Id
    Long appId = appDeployRequest.getAppId();
    ThrowUtils.throwIf(appId == null || appId <= 0, ErrorCode.PARAMS_ERROR, "应用Id不能为空");
    // 获取当前登录用户
    User loginUser = userService.getLoginUser(request);
    // 调用服务部署应用
    String deployUrl = appService.deployApp(appId, loginUser);
    // 返回部署成功的 URL
    return ResultUtils.success(deployUrl);
}
```

**接口特点**：
- **RESTful 设计**：使用 POST 方法进行部署操作
- **参数校验**：严格校验应用ID和用户登录状态
- **权限控制**：确保只有应用所有者可以部署
- **返回部署URL**：部署成功后返回可访问的完整URL

**2. Service 层 - 部署业务逻辑**

```java
@Override
public String deployApp(Long appId, User loginUser) {
    // 1.参数校验
    ThrowUtils.throwIf(appId == null || appId <= 0, ErrorCode.PARAMS_ERROR, "应用ID错误");
    ThrowUtils.throwIf(loginUser == null, ErrorCode.NOT_LOGIN_ERROR, "用户未登录");
    
    // 2.查询应用信息
    App app = this.getById(appId);
    ThrowUtils.throwIf(app == null, ErrorCode.NOT_FOUND_ERROR, "应用不存在");
    
    // 3.权限校验，仅本人可以部署自己的应用
    if (!app.getUserId().equals(loginUser.getId())) {
        throw new BusinessException(ErrorCode.NO_AUTH_ERROR, "无权限部署该应用");
    }
    
    // 4.检查是否已有 deployKey
    String deployKey = app.getDeployKey();
    // 如果没有，则生成 6 位 deployKey (字母 + 数字)
    if (StrUtil.isBlank(deployKey)) {
        deployKey = RandomUtil.randomString(6);
    }

    // 5.获取代码生成类型，获取原始代码生成路径（应用访问目录）
    String codeGenType = app.getCodeGenType();
    String sourceDirName = codeGenType + "_" + appId;
    // 生成原始文件路径
    String sourceDirPath = AppConstant.CODE_OUTPUT_ROOT_DIR + File.separator + sourceDirName;

    // 6.检查路径是否存在
    File sourceDir = new File(sourceDirPath);
    // 如果文件路径不存在 或者 路径不是一个目录形式，报错
    if (!sourceDir.exists() || !sourceDir.isDirectory()) {
        throw new BusinessException(ErrorCode.SYSTEM_ERROR, "应用代码路径不存在，请先生成应用");
    }

    // 7.复制文件到部署目录
    String deployDirPath = AppConstant.CODE_DEPLOY_ROOT_DIR + File.separator + deployKey;
    // FileUtil.copyContent(原始文件目录， 目标文件目录， 是否覆盖内容)
    try {
        FileUtil.copyContent(sourceDir, new File(deployDirPath), true);
    } catch (Exception e) {
        throw new BusinessException(ErrorCode.SYSTEM_ERROR, "应用部署失败：" + e.getMessage());
    }

    // 8.更新数据库
    App updateApp = new App();
    updateApp.setId(appId);
    updateApp.setDeployKey(deployKey);
    updateApp.setDeployedTime(LocalDateTime.now());
    boolean updateResult = this.updateById(updateApp);
    ThrowUtils.throwIf(!updateResult, ErrorCode.OPERATION_ERROR, "更新应用部署信息失败");
    
    // 9.返回可访问的 URL 地址
    return String.format("%s/%s/", AppConstant.CODE_DEPLOY_HOST, deployKey);
}
```

**业务逻辑流程**：
1. **参数校验**：验证应用ID和用户登录状态
2. **应用验证**：检查应用是否存在
3. **权限控制**：只有应用所有者可以部署
4. **生成部署标识**：首次部署生成6位随机deployKey
5. **路径验证**：检查代码生成目录是否存在
6. **文件复制**：将代码从生成目录复制到部署目录
7. **数据库更新**：记录deployKey和部署时间
8. **返回URL**：返回可访问的部署地址

### 🌐 静态资源访问方案

#### 方案对比

**方案一：SpringBoot内置Tomcat（备用方案）**

```java
@RestController
@RequestMapping("/static")
public class StaticResourceController {
    
    @GetMapping("/{deployKey}/**")
    public ResponseEntity<Resource> serveStaticResource(
            @PathVariable String deployKey,
            HttpServletRequest request) {
        // 获取资源路径
        String resourcePath = (String) request.getAttribute(HandlerMapping.PATH_WITHIN_HANDLER_MAPPING_ATTRIBUTE);
        resourcePath = resourcePath.substring(("/static/" + deployKey).length());
        
        // 默认返回 index.html
        if (resourcePath.equals("/")) {
            resourcePath = "/index.html";
        }
        
        // 构建文件路径
        String filePath = PREVIEW_ROOT_DIR + "/" + deployKey + resourcePath;
        File file = new File(filePath);
        
        // 检查文件是否存在
        if (!file.exists()) {
            return ResponseEntity.notFound().build();
        }
        
        // 返回文件资源
        Resource resource = new FileSystemResource(file);
        return ResponseEntity.ok()
                .header("Content-Type", getContentTypeWithCharset(filePath))
                .body(resource);
    }
}
```

**优点**：
- 无需额外配置
- 开发环境快速测试
- 代码级别控制

**缺点**：
- 性能较低
- 占用应用资源
- 不适合生产环境

**方案二：Nginx静态资源映射（推荐方案）**

**Nginx配置示例**：

```nginx
server {
    listen 80;
    server_name localhost;
    
    # 部署应用访问
    location / {
        root "D:/0 Postgraduate/JAVA/JAVA Project/Java_Project_Practices/Yupi_Projects/yu-ai-code-mother/YuCodeMother-Backend/tmp/code_deploy";
        index index.html;
        try_files $uri $uri/ /index.html;
    }
    
    # 后端API代理
    location /api/ {
        proxy_pass http://localhost:8123/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

**配置说明**：
- **root指令**：指向部署目录，路径需要用引号括起来（Windows路径有空格）
- **index指令**：默认首页为index.html
- **try_files指令**：支持SPA应用的路由
- **proxy_pass指令**：代理后端API请求

**优点**：
- **高性能**：Nginx专门优化静态资源服务
- **低资源占用**：不占用应用服务器资源
- **生产级别**：适合生产环境部署
- **负载均衡**：可配置多台服务器

**访问方式**：
```
http://localhost/{deployKey}/
```

例如：
```
http://localhost/abc123/
http://localhost/xyz789/
```

### 🐛 Bug 修复与优化

#### 1. Windows路径空格问题

**问题**：Nginx配置中路径包含空格导致解析失败

**错误信息**：
```
nginx: [emerg] invalid number of arguments in "root" directive
```

**修复**：
```nginx
# ❌ 错误
root D:/0 Postgraduate/JAVA/JAVA Project/...;

# ✅ 正确
root "D:/0 Postgraduate/JAVA/JAVA Project/...";
```

#### 2. 端口占用问题

**问题**：80端口被IIS或HTTP.sys占用

**错误信息**：
```
nginx: [emerg] bind() to 0.0.0.0:80 failed (10013: An attempt was made to access a socket in a way forbidden by its access permissions)
```

**解决方案**：
```cmd
# 停止IIS服务
net stop w3svc /y

# 停止HTTP服务
net stop was /y
net stop http /y

# 禁用开机自启（可选）
sc config was start=disabled
sc config http start=disabled
```

#### 3. 文件覆盖策略

**问题**：重复部署时文件冲突

**解决方案**：
```java
// 使用覆盖模式复制文件
FileUtil.copyContent(sourceDir, new File(deployDirPath), true);
```

**优势**：
- 支持重复部署
- 自动更新文件
- 保持deployKey不变

#### 4. 路径不存在处理

**问题**：代码未生成就尝试部署

**解决方案**：
```java
File sourceDir = new File(sourceDirPath);
if (!sourceDir.exists() || !sourceDir.isDirectory()) {
```

### 📝 最佳实践

#### 1. Nginx配置建议

**生产环境配置**：

```nginx
server {
    listen 80;
    server_name yourdomain.com;
    
    # 启用gzip压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript;
    
    # 静态资源缓存
    location ~* \.(jpg|jpeg|png|gif|ico|css|js)$ {
        expires 7d;
        add_header Cache-Control "public, immutable";
    }
    
    # 部署应用访问
    location / {
        root "/path/to/code_deploy";
        index index.html;
        try_files $uri $uri/ /index.html;
    }
    
    # 后端API代理
    location /api/ {
        proxy_pass http://localhost:8123/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

#### 2. 部署目录管理

**定期清理策略**：
```java
// 清理30天未访问的部署
public void cleanOldDeployments() {
    LocalDateTime threshold = LocalDateTime.now().minusDays(30);
    List<App> oldApps = appService.list(
        QueryWrapper.create()
            .lt("deployedTime", threshold)
    );
    // 删除文件和数据库记录
}
```

#### 3. 监控与日志

**访问日志**：
```nginx
access_log /var/log/nginx/deploy_access.log;
error_log /var/log/nginx/deploy_error.log;
```

**应用日志**：
```java
log.info("应用部署成功 - ID: {}, deployKey: {}, URL: {}", 
    appId, deployKey, deployUrl);
```

#### 4. 安全加固

**防止目录遍历**：
```nginx
location / {
    # 禁止访问隐藏文件
    location ~ /\. {
        deny all;
    }
}
```

**限流配置**：
```nginx
limit_req_zone $binary_remote_addr zone=deploy:10m rate=10r/s;

location /api/app/deploy {
    limit_req zone=deploy burst=5;
}
```
