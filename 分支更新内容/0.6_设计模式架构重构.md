🎉 **YuCodeMother v0.6 版本发布说明**

### 📋 版本概述

本次 v0.6 版本是项目的重要架构优化版本，在 v0.5 流式输出的基础上，进行了全面的代码重构。通过引入**模板方法模式**、**策略模式**和**执行器模式**，实现了代码解析和文件保存逻辑的模块化、可扩展和可维护，大幅提升了代码质量和架构设计水平。

### ✨ 新增功能

#### 🏗️ 架构重构 - 设计模式升级

**1. 模板方法模式（Template Method Pattern）**

引入抽象模板类 `CodeFileSaverTemplate`，定义文件保存的标准流程：

```java
public abstract class CodeFileSaverTemplate<T> {
    
    /**
     * 保存代码的流程 - 使用 final 防止子类覆盖
     */
    public final File saveCode(T result) {
        // 1. 验证输入
        validateInput(result);
        // 2. 构建唯一目录
        String baseDirPath = buildUniqueDir();
        // 3. 保存文件（具体实现交给子类）
        saveFiles(result, baseDirPath);
        // 4. 返回文件目录对象
        return new File(baseDirPath);
    }
    
    // 抽象方法 - 由子类实现
    protected abstract void saveFiles(T result, String baseDirPath);
    protected abstract CodeGenTypeEnum getCodeType();
    
    // 钩子方法 - 子类可选择性覆盖
    protected void validateInput(T result) {
        ThrowUtils.throwIf(result == null, ErrorCode.SYSTEM_ERROR, "代码结果对象不能为空");
    }
}
```

**设计优势**：
- **流程标准化**：所有保存器遵循统一的保存流程
- **代码复用**：公共逻辑（目录创建、文件写入）在父类实现
- **扩展灵活**：子类只需实现特定的保存逻辑
- **防止篡改**：使用 `final` 确保流程不被修改

**2. 具体实现 - HTML 文件保存器**

```java
public class HtmlCodeFileSaverTemplate extends CodeFileSaverTemplate<HtmlCodeResult> {
    
    @Override
    protected CodeGenTypeEnum getCodeType() {
        return CodeGenTypeEnum.HTML;
    }
    
    @Override
    protected void saveFiles(HtmlCodeResult result, String baseDirPath) {
        // 调用父类的 writeToFile() 方法
        writeToFile(baseDirPath, "index.html", result.getHtmlCode());
    }
    
    @Override
    protected void validateInput(HtmlCodeResult result) {
        super.validateInput(result);
        // 额外校验：HTML 代码不能为空
        if (StrUtil.isBlank(result.getHtmlCode())) {
            throw new BusinessException(ErrorCode.PARAMS_ERROR, "HTML代码不能为空");
        }
    }
}
```

**实现特点**：
- **类型安全**：泛型 `<HtmlCodeResult>` 确保类型正确
- **职责单一**：只负责 HTML 文件的保存逻辑
- **可扩展验证**：可以添加特定的校验规则

**3. 多文件保存器**

```java
public class MultiFileCodeFileSaverTemplate extends CodeFileSaverTemplate<MultiFileCodeResult> {
    
    @Override
    protected CodeGenTypeEnum getCodeType() {
        return CodeGenTypeEnum.MULTI_FILE;
    }
    
    @Override
    protected void saveFiles(MultiFileCodeResult result, String baseDirPath) {
        // 保存三个文件
        writeToFile(baseDirPath, "index.html", result.getHtmlCode());
        writeToFile(baseDirPath, "style.css", result.getCssCode());
        writeToFile(baseDirPath, "script.js", result.getJsCode());
    }
    
    @Override
    protected void validateInput(MultiFileCodeResult result) {
        super.validateInput(result);
        // 至少要有一个文件内容不为空
        boolean hasContent = StrUtil.isNotBlank(result.getHtmlCode()) ||
                            StrUtil.isNotBlank(result.getCssCode()) ||
                            StrUtil.isNotBlank(result.getJsCode());
        if (!hasContent) {
            throw new BusinessException(ErrorCode.PARAMS_ERROR, "至少需要一个文件内容");
        }
    }
}
```

#### 🎯 策略模式 + 执行器模式

**1. 代码解析器接口**

定义统一的解析器接口：

```java
public interface CodeParser<T> {
    /**
     * 解析代码内容
     * @param codeContent 原始代码内容
     * @return 解析后的结果对象
     */
    T parseCode(String codeContent);
}
```

**设计优势**：
- **接口统一**：所有解析器实现相同接口
- **泛型支持**：返回类型由具体实现决定
- **易于测试**：可以轻松 Mock 和单元测试

**2. HTML 代码解析器**

```java
public class HtmlCodeParser implements CodeParser<HtmlCodeResult> {
    
    private static final Pattern HTML_CODE_PATTERN = 
        Pattern.compile("```html\\s*\\n([\\s\\S]*?)```", Pattern.CASE_INSENSITIVE);
    
    @Override
    public HtmlCodeResult parseCode(String codeContent) {
        HtmlCodeResult result = new HtmlCodeResult();
        String htmlCode = extractHtmlCode(codeContent);
        
        if (htmlCode != null && !htmlCode.trim().isEmpty()) {
            result.setHtmlCode(htmlCode.trim());
        } else {
            // 容错：如果没找到代码块，将整个内容作为 HTML
            result.setHtmlCode(codeContent.trim());
        }
        return result;
    }
    
    private String extractHtmlCode(String content) {
        Matcher matcher = HTML_CODE_PATTERN.matcher(content);
        return matcher.find() ? matcher.group(1) : null;
    }
}
```

**3. 多文件代码解析器**

```java
public class MultiFileCodeParser implements CodeParser<MultiFileCodeResult> {
    
    private static final Pattern HTML_CODE_PATTERN = 
        Pattern.compile("```html\\s*\\n([\\s\\S]*?)```", Pattern.CASE_INSENSITIVE);
    private static final Pattern CSS_CODE_PATTERN = 
        Pattern.compile("```css\\s*\\n([\\s\\S]*?)```", Pattern.CASE_INSENSITIVE);
    private static final Pattern JS_CODE_PATTERN = 
        Pattern.compile("```(?:js|javascript)\\s*\\n([\\s\\S]*?)```", Pattern.CASE_INSENSITIVE);
    
    @Override
    public MultiFileCodeResult parseCode(String codeContent) {
        MultiFileCodeResult result = new MultiFileCodeResult();
        
        // 提取各类代码
        String htmlCode = extractCodeByPattern(codeContent, HTML_CODE_PATTERN);
        String cssCode = extractCodeByPattern(codeContent, CSS_CODE_PATTERN);
        String jsCode = extractCodeByPattern(codeContent, JS_CODE_PATTERN);
        
        // 设置代码内容
        if (htmlCode != null && !htmlCode.trim().isEmpty()) {
            result.setHtmlCode(htmlCode.trim());
        }
        if (cssCode != null && !cssCode.trim().isEmpty()) {
            result.setCssCode(cssCode.trim());
        }
        if (jsCode != null && !jsCode.trim().isEmpty()) {
            result.setJsCode(jsCode.trim());
        }
        
        return result;
    }
    
    private String extractCodeByPattern(String content, Pattern pattern) {
        Matcher matcher = pattern.matcher(content);
        return matcher.find() ? matcher.group(1) : null;
    }
}
```

**4. 代码解析执行器**

```java
public class CodeParserExecutor {
    
    private static final HtmlCodeParser htmlCodeParser = new HtmlCodeParser();
    private static final MultiFileCodeParser multiFileCodeParser = new MultiFileCodeParser();
    
    /**
     * 根据代码生成类型执行相应的解析器
     */
    public static Object executeParser(String codeContent, CodeGenTypeEnum codeGenTypeEnum) {
        return switch (codeGenTypeEnum) {
            case HTML -> htmlCodeParser.parseCode(codeContent);
            case MULTI_FILE -> multiFileCodeParser.parseCode(codeContent);
            default -> throw new BusinessException(ErrorCode.SYSTEM_ERROR, "不支持的代码生成类型");
        };
    }
}
```

**执行器优势**：
- **统一入口**：所有解析操作通过执行器调用
- **单例模式**：解析器实例复用，节省资源
- **类型路由**：根据枚举自动选择解析器

**5. 文件保存执行器**

```java
public class CodeFileSaverExecutor {
    
    private static final HtmlCodeFileSaverTemplate htmlCodeFileSaver = 
        new HtmlCodeFileSaverTemplate();
    private static final MultiFileCodeFileSaverTemplate multiFileCodeFileSaver = 
        new MultiFileCodeFileSaverTemplate();
    
    /**
     * 根据代码生成类型执行相应的保存器
     */
    public static File executeSaver(Object codeResult, CodeGenTypeEnum codeGenType) {
        return switch (codeGenType) {
            case HTML -> htmlCodeFileSaver.saveCode((HtmlCodeResult) codeResult);
            case MULTI_FILE -> multiFileCodeFileSaver.saveCode((MultiFileCodeResult) codeResult);
            default -> throw new BusinessException(ErrorCode.SYSTEM_ERROR, "不支持的代码生成类型");
        };
    }
}
```

### 🔧 技术亮点

#### 1. 模板方法模式的完整实现

**模板方法模式的三个关键要素**：

**（1）模板方法（Template Method）**
```java
public final File saveCode(T result) {
    validateInput(result);
    String baseDirPath = buildUniqueDir();
    saveFiles(result, baseDirPath);
    return new File(baseDirPath);
}
```
- 使用 `final` 防止子类覆盖
- 定义算法骨架和执行顺序
- 调用抽象方法和钩子方法

**（2）抽象方法（Abstract Method）**
```java
protected abstract void saveFiles(T result, String baseDirPath);
protected abstract CodeGenTypeEnum getCodeType();
```
- 必须由子类实现
- 定义算法中的可变部分

**（3）钩子方法（Hook Method）**
```java
protected void validateInput(T result) {
    ThrowUtils.throwIf(result == null, ErrorCode.SYSTEM_ERROR, "代码结果对象不能为空");
}
```
- 提供默认实现
- 子类可选择性覆盖
- 允许子类扩展行为

#### 2. 泛型的高级应用

**泛型模板类**：
```java
public abstract class CodeFileSaverTemplate<T> {
    public final File saveCode(T result) { ... }
    protected abstract void saveFiles(T result, String baseDirPath);
}
```

**具体类型绑定**：
```java
public class HtmlCodeFileSaverTemplate extends CodeFileSaverTemplate<HtmlCodeResult> {
    // T 被绑定为 HtmlCodeResult
}
```

**优势**：
- **类型安全**：编译时检查类型
- **代码复用**：一个模板支持多种类型
- **避免强制转换**：不需要 `(HtmlCodeResult)` 转换

#### 3. 策略模式 vs 模板方法模式

**选择依据**：

| 场景 | 模式选择 | 原因 |
|------|---------|------|
| 方法参数相同 | 模板方法模式 | 可以定义统一的模板方法 |
| 方法参数不同 | 策略模式 + 执行器 | 无法定义统一的模板方法 |

**本项目的应用**：
- **文件保存**：参数相同 `(T result, String baseDirPath)` → 模板方法模式
- **代码解析**：参数相同 `(String codeContent)` → 策略模式 + 执行器

#### 4. 执行器模式（Executor Pattern）

**执行器模式的作用**：
- **统一入口**：提供单一的调用入口
- **类型路由**：根据类型选择具体实现
- **实例管理**：管理策略实例的生命周期

**实现方式**：
```java
public class CodeParserExecutor {
    // 单例实例
    private static final HtmlCodeParser htmlCodeParser = new HtmlCodeParser();
    private static final MultiFileCodeParser multiFileCodeParser = new MultiFileCodeParser();
    
    // 统一入口
    public static Object executeParser(String codeContent, CodeGenTypeEnum type) {
        return switch (type) {
            case HTML -> htmlCodeParser.parseCode(codeContent);
            case MULTI_FILE -> multiFileCodeParser.parseCode(codeContent);
            default -> throw new BusinessException(...);
        };
    }
}
```

#### 5. 代码复用的最佳实践

**父类提供的公共方法**：

```java
public abstract class CodeFileSaverTemplate<T> {
    
    // 公共方法 1：写入单个文件
    protected final void writeToFile(String dirPath, String filename, String content) {
        if (StrUtil.isNotBlank(content)) {
            String filePath = dirPath + File.separator + filename;
            FileUtil.writeString(content, filePath, StandardCharsets.UTF_8);
        }
    }
    
    // 公共方法 2：构建唯一目录
    protected String buildUniqueDir() {
        String codeType = getCodeType().getValue();
        String uniqueDirName = StrUtil.format("{}_{}", codeType, IdUtil.getSnowflakeNextIdStr());
        String dirPath = FILE_SAVE_ROOT_DIR + File.separator + uniqueDirName;
        FileUtil.mkdir(dirPath);
        return dirPath;
    }
}
```

**子类直接调用**：
```java
public class HtmlCodeFileSaverTemplate extends CodeFileSaverTemplate<HtmlCodeResult> {
    @Override
    protected void saveFiles(HtmlCodeResult result, String baseDirPath) {
        // 直接调用父类方法
        writeToFile(baseDirPath, "index.html", result.getHtmlCode());
    }
}
```

### 📊 架构对比

#### v0.5 架构（重构前）

```

    ↓

    ↓

**问题**：

    ↓
CodeFileSaverExecutor.executeSaver()
    ↓
    ├─→ HtmlCodeFileSaverTemplate.saveCode()
    └─→ MultiFileCodeFileSaverTemplate.saveCode()
```

**优势**：
- 模块化设计，职责清晰
- 代码复用，减少重复
- 易于扩展，符合开闭原则
- 面向对象，设计模式应用

### 📦 设计模式总结

#### 本版本应用的设计模式

| 设计模式 | 应用场景 | 核心类 |
|---------|---------|--------|
| **模板方法模式** | 文件保存流程 | `CodeFileSaverTemplate` |
| **策略模式** | 代码解析策略 | `CodeParser` 接口 |
| **执行器模式** | 统一调用入口 | `CodeParserExecutor`<br>`CodeFileSaverExecutor` |
| **门面模式** | 简化客户端调用 | `AiCodeGeneratorFacade` |
| **工厂模式** | AI 服务创建 | `AiCodeGeneratorServiceFactory` |

#### 设计模式的协作关系

```
门面模式（Facade）
    ↓
执行器模式（Executor）
    ↓
    ├─→ 策略模式（Strategy）- 代码解析
    └─→ 模板方法模式（Template Method）- 文件保存
```

### 🎯 核心优势

#### 1. 高度可扩展

**新增代码类型只需 4 步**：
1. 添加枚举值
2. 实现解析器
3. 实现保存器
4. 更新执行器

**无需修改**：
- 门面类
- 模板类
- 其他实现类

#### 2. 代码复用最大化

**父类提供的公共功能**：
- 目录创建
- 文件写入
- 参数校验
- 异常处理

**子类只需关注**：
- 特定的保存逻辑
- 特定的校验规则

#### 3. 类型安全

**泛型保证类型安全**：
```java
// 编译时检查类型
CodeFileSaverTemplate<HtmlCodeResult> saver = new HtmlCodeFileSaverTemplate();
File result = saver.saveCode(htmlCodeResult);  // ✅ 类型正确
File result = saver.saveCode(multiFileResult); // ❌ 编译错误
```

#### 4. 易于测试

**每个类职责单一**：
- 解析器只负责解析
- 保存器只负责保存
- 执行器只负责路由

**便于单元测试**：
```java
@Test
void testHtmlCodeParser() {
    HtmlCodeParser parser = new HtmlCodeParser();
    String input = "```html\n<html></html>\n```";
    HtmlCodeResult result = parser.parseCode(input);
    assertNotNull(result.getHtmlCode());
}
```

#### 5. 符合 SOLID 原则

**单一职责原则（SRP）**：
- 每个类只有一个职责
- 解析器只解析，保存器只保存

**开闭原则（OCP）**：
- 对扩展开放：可以添加新的实现类
- 对修改关闭：无需修改现有代码

**里氏替换原则（LSP）**：
- 子类可以替换父类
- 所有保存器都可以通过模板类调用

**接口隔离原则（ISP）**：
- 接口精简，只定义必要方法
- `CodeParser` 只有一个 `parseCode` 方法

**依赖倒置原则（DIP）**：
- 依赖抽象而非具体实现
- 执行器依赖接口而非具体类

#### 1. 如何选择设计模式

**模板方法模式 vs 策略模式**：
- **相同流程，不同实现** → 模板方法模式
- **不同策略，灵活切换** → 策略模式

**何时使用执行器模式**：
- 需要统一的调用入口
- 需要管理多个策略实例
- 需要根据类型路由到不同实现

#### 2. 泛型的使用建议

**何时使用泛型**：
- 需要类型安全
- 需要代码复用
- 需要避免强制转换

**泛型的限制**：
- 不能创建泛型数组
- 不能使用基本类型
- 运行时类型擦除

#### 3. 代码复用的技巧

**提取公共逻辑到父类**：
- 目录创建
- 文件写入
- 参数校验

**使用钩子方法**：
- 提供默认实现
- 允许子类覆盖
- 保持灵活性
