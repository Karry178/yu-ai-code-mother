### ✨ 新增功能

#### 🌊 SSE 流式输出核心功能

**1. Controller 层 - SSE 端点实现**

实现了标准的 SSE 接口，支持实时推送 AI 生成的代码流：

```java
@GetMapping(value = "/chat/gen/code", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<ServerSentEvent<String>> chatToGenCode(@RequestParam Long appId,
                                  @RequestParam String message,
                                  HttpServletRequest request) {
    // 1.参数校验
    ThrowUtils.throwIf(appId == null || appId <= 0, ErrorCode.PARAMS_ERROR, "应用ID错误");
    ThrowUtils.throwIf(StrUtil.isBlank(message), ErrorCode.PARAMS_ERROR, "提示词不能为空");
    
    // 2.获取当前登录用户
    User loginUser = userService.getLoginUser(request);
    
    // 3.调用 Service 层生成代码（SSE流式返回）
    Flux<String> contentFlux = appService.chatToGenCode(appId, message, loginUser);
    
    // 4.转换为 ServerSentEvent 格式
    return contentFlux
            .map(chunk -> {
                // 封装数据格式：{"d": "代码片段"}
                Map<String, String> wrapper = Map.of("d", chunk);
                String jsonData = JSONUtil.toJsonStr(wrapper);
                
                // 封装为 SSE 事件
                return ServerSentEvent.<String>builder()
                        .data(jsonData)
                        .build();
            })
            .concatWith(Mono.just(
                    // 发送结束事件
                    ServerSentEvent.<String>builder()
                        .event("done")
                        .data("")
                        .build()
            ));
}
```

**接口特点**：
- **标准 SSE 协议**：使用 `text/event-stream` 媒体类型
- **JSON 数据封装**：每个代码片段封装为 `{"d": "chunk"}` 格式
- **结束事件标记**：发送 `done` 事件通知前端流结束
- **权限校验**：确保只有应用所有者可以生成代码

**2. Service 层 - 业务逻辑封装**

```java
@Override
public Flux<String> chatToGenCode(Long appId, String message, User loginUser) {
    // 1.参数校验
    if (appId == null || appId <= 0) {
        throw new BusinessException(ErrorCode.PARAMS_ERROR, "应用Id错误");
    }
    ThrowUtils.throwIf(StrUtil.isBlank(message), ErrorCode.PARAMS_ERROR, "提示词不能为空");
    
    // 2.查询应用信息
    App app = this.getById(appId);
    ThrowUtils.throwIf(app == null, ErrorCode.NOT_FOUND_ERROR, "应用不存在");
    
    // 3.权限校验，仅本人可以和自己的应用对话
    if (!app.getUserId().equals(loginUser.getId())) {
        throw new BusinessException(ErrorCode.NO_AUTH_ERROR, "无权限访问该应用");
    }
    
    // 4.获取应用的代码生成类型
    String codeGenType = app.getCodeGenType();
    CodeGenTypeEnum codeGenTypeEnum = CodeGenTypeEnum.getEnumByValue(codeGenType);
    ThrowUtils.throwIf(codeGenTypeEnum == null, ErrorCode.PARAMS_ERROR, "应用代码生成类型错误");
    
    // 5.调用AI生成代码
    return aiCodeGeneratorFacade.generateAndSaveCodeStream(message, codeGenTypeEnum, appId);
}
```

**业务逻辑**：
- **应用验证**：检查应用是否存在
- **权限控制**：只有应用所有者可以生成代码
- **类型转换**：将字符串类型转换为枚举类型
- **门面调用**：通过门面模式调用 AI 代码生成服务

**3. 门面层 - 流式代码生成与保存**

```java
public Flux<String> generateAndSaveCodeStream(String userMessage, CodeGenTypeEnum codeGenTypeEnum, Long appId) {
    // 1. 校验
    if (codeGenTypeEnum == null) {
        throw new BusinessException(ErrorCode.PARAMS_ERROR, "生成类型不能为空");
    }
    
    // 2. 根据类型路由到不同的生成器
    return switch (codeGenTypeEnum) {
        case HTML -> {
            Flux<String> codeStream = aiCodeGeneratorService.generateHtmlCodeStream(userMessage);
            yield processCodeStream(codeStream, CodeGenTypeEnum.HTML, appId);
        }
        case MULTI_FILE -> {
            Flux<String> codeStream = aiCodeGeneratorService.generateMultiFileCodeStream(userMessage);
            yield processCodeStream(codeStream, CodeGenTypeEnum.MULTI_FILE, appId);
        }
        default -> {
            String errorMessage = "不支持的生成类型" + codeGenTypeEnum.getValue();
            throw new BusinessException(ErrorCode.SYSTEM_ERROR, errorMessage);
        }
    };
}
```

**4. 流式处理核心逻辑**

```java
private Flux<String> processCodeStream(Flux<String> codeStream, CodeGenTypeEnum codeGenType, Long appId) {
    // 字符串拼接器：用于收集所有代码片段
    StringBuilder codeBuilder = new StringBuilder();
    
    // 使用 cache() 缓存流数据，允许多次订阅
    return codeStream.cache()
            .doOnNext(chunk -> {
                // 实时收集代码片段
                codeBuilder.append(chunk);
            })
            .doOnComplete(() -> {
                // 流结束后，保存代码
                try {
                    String completeCode = codeBuilder.toString();
                    
                    // 使用执行器解析代码
                    Object parsedResult = CodeParserExecutor.executeParser(completeCode, codeGenType);
                    
                    // 使用执行器保存代码
                    File saveDir = CodeFileSaverExecutor.executeSaver(parsedResult, codeGenType, appId);
                    
                    // 记录日志
                    log.info("文件保存成功，目录为：{}", saveDir.getAbsolutePath());
                } catch (Exception e) {
                    log.error("文件保存失败：{}", e.getMessage());
                }
            });
}
```

**流式处理特点**：
- **`.cache()`**：将冷流转换为热流，支持多个订阅者
- **`.doOnNext()`**：实时处理每个数据块，收集代码片段
- **`.doOnComplete()`**：流结束时触发文件保存逻辑
- **非阻塞**：整个过程异步执行，不阻塞主线程
- **自动保存**：后台自动收集并保存完整代码

### 🔧 技术亮点

#### 1. SSE 协议实现

**SSE vs WebSocket**：

| 特性 | SSE | WebSocket |
|------|-----|-----------|
| **通信方向** | 单向（服务器→客户端） | 双向 |
| **协议** | HTTP | WebSocket 协议 |
| **复杂度** | 简单 | 复杂 |
| **浏览器支持** | 广泛 | 广泛 |
| **自动重连** | 内置 | 需手动实现 |
| **适用场景** | 实时推送、进度更新 | 实时聊天、游戏 |

**为什么选择 SSE**：
- **单向推送**：AI 代码生成只需服务器推送到客户端
- **简单易用**：基于 HTTP，无需额外协议
- **自动重连**：浏览器自动处理断线重连
- **轻量级**：相比 WebSocket 更轻量

#### 2. 响应式编程模型

**Flux 流式处理**：

```java
Flux<String> codeStream = aiCodeGeneratorService.generateHtmlCodeStream(userMessage);

// 流式处理管道
codeStream
    .cache()                    // 转换为热流
    .doOnNext(chunk -> {        // 处理每个数据块
        // 实时推送到前端
        // 后台收集代码
    })
    .doOnComplete(() -> {       // 流结束时
        // 保存文件
    })
    .doOnError(error -> {       // 错误处理
        // 记录日志
    });
```

**优势**：
- **非阻塞**：不占用线程等待
- **背压支持**：自动处理生产者和消费者速度不匹配
- **组合性强**：可以轻松组合多个操作
- **资源高效**：一个线程可以处理多个请求

#### 3. 冷流 vs 热流

**冷流（Cold Stream）**：
- 每次订阅都重新执行数据源
- 类似于点播视频，每个观众从头开始看
- LangChain4j 默认返回冷流

**热流（Hot Stream）**：
- 数据源只执行一次，多个订阅者共享数据
- 类似于直播，所有观众看同一个流
- 使用 `.cache()` 转换为热流

**为什么需要 cache()**：

```java
// ❌ 错误：冷流被多次订阅会导致多次调用 AI
Flux<String> result = aiCodeGeneratorService.generateHtmlCodeStream(userMessage);
return result.doOnNext(...).doOnComplete(...);

// ✅ 正确：使用 cache() 转换为热流
return result.cache()
        .doOnNext(...)
        .doOnComplete(...);
```

#### 4. 数据格式设计

**SSE 数据格式**：

```
data: {"d":"<!DOCTYPE html>\n"}

data: {"d":"<html>\n"}

data: {"d":"<head>\n"}

event: done
data: 

```

**设计考虑**：
- **JSON 封装**：便于前端解析
- **`d` 字段**：简短的字段名减少传输量
- **结束事件**：明确告知前端流已结束
- **错误处理**：可以发送 `error` 事件

#### 5. 异步文件保存

**流式处理流程**：

```
AI 生成流 (Flux<String>)
    ↓
.cache() 转换为热流
    ↓
    ├─→ doOnNext() 实时推送到前端
    │   └─→ SSE 事件流
    │
    ├─→ doOnNext() 后台收集代码
    │   └─→ StringBuilder.append(chunk)
    │
    └─→ doOnComplete() 流结束时保存文件
        ├─→ CodeParserExecutor.executeParser()
        ├─→ CodeFileSaverExecutor.executeSaver()
        └─→ log.info("文件保存成功")
```

**优势**：
- **实时反馈**：前端可以实时显示生成进度
- **自动保存**：后台自动收集并保存完整代码
- **非阻塞**：不影响其他请求的处理
- **容错性**：异常时记录日志，不影响流的传输

### 📝 最佳实践

#### 1. SSE 连接管理

**前端最佳实践**：

```javascript
class SSEManager {
  constructor(url) {
    this.url = url;
    this.eventSource = null;
    this.reconnectAttempts = 0;
    this.maxReconnectAttempts = 3;
  }
  
  connect(onMessage, onDone, onError) {
    this.eventSource = new EventSource(this.url);
    
    this.eventSource.onmessage = onMessage;
    this.eventSource.addEventListener('done', onDone);
    
    this.eventSource.onerror = (error) => {
      if (this.reconnectAttempts < this.maxReconnectAttempts) {
        this.reconnectAttempts++;
        setTimeout(() => this.connect(onMessage, onDone, onError), 1000);
      } else {
        onError(error);
        this.close();
      }
    };
  }
  
  close() {
    if (this.eventSource) {
      this.eventSource.close();
      this.eventSource = null;
    }
  }
}
```
